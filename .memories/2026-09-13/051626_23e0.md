## Merged origin/main into kae36/personal (Task 1 of sync-upstream-and-harden-security)

**What:** Ran `git merge origin/main --no-commit` on `worktree-sync-upstream-security` (HEAD `ed47daf`, merge-base `f16479e3`, origin/main tip `67791060`) and resolved all resulting conflicts.

**Why:** `kae36/personal` had fallen ~350 commits behind upstream `origin/main` while carrying its own unmerged Aug 5 Supabase security fixes. This merge brings the fork current without losing those fixes.

**How — conflict resolution (plan-mismatch, corrected mid-task):**
- Actual conflict set was 4 files, not the brief's predicted 6. 2 matched exactly (add/add): `schemas/crm-person-tiers/schema.sql`, `recipes/brain-health-monitoring/ops-views.sql` — resolved by keeping HEAD (`git checkout --ours`), preserving the security fixes.
- 3 files the brief expected to conflict (`recipes/lint-sweep/views.sql`, `schemas/thought-audit/author-session-id.sql`, `.gitignore`) auto-merged cleanly with zero drift from `kae36/personal` — verified via empty `git diff kae36/personal -- <path>`.
- 2 unexpected UU conflicts appeared instead of the brief's predicted `ob1-gate.yml` modify/delete: `.github/workflows/ob1-gate-v2.yml` and `.github/workflows/ob1-pr-followups.yml`. Root cause: git's rename detection paired HEAD's modified `ob1-gate.yml` (fix from commit `b35d5a6`) with origin/main's newly-added `ob1-gate-v2.yml`, producing a real content merge instead of a clean rename. Stopped and reported BLOCKED with exact conflict content; lead confirmed this was the plan's pre-approved "take origin/main's rename wholesale" recommendation, just manifesting via a different git mechanism than predicted. Resolved by taking origin/main's content entirely for both files (`git checkout --theirs`) — reasoning: both HEAD's and origin/main's fixes target the same GitHub Actions "empty workflow runs" bug via different mechanisms, this workflow only triggers on `branches: [main]` while this fork's default branch is `kae36/personal` (never fires here), so there's zero live blast radius either way, and hand-merging the two trigger/condition sets would risk reintroducing the bug either fix was chasing.
- `ob1-gate.yml` resolved to a clean rename (`R`) into `ob1-gate-v2.yml` once both sides were reconciled.

**Verification:** `git diff --check` clean, `git grep "^<<<<<<<"` finds zero markers repo-wide, `git diff origin/main -- ob1-gate-v2.yml/ob1-pr-followups.yml/ob1-gate.yml` all empty (theirs applied exactly), `git diff kae36/personal -- schemas/crm-person-tiers/schema.sql recipes/brain-health-monitoring/ops-views.sql` empty (security fixes byte-identical, survived merge).

**Impact:** Merge commit becomes the base tree for Task 2 (schemas/enhanced-thoughts/schema.sql review) and Task 3 (repo-wide SQL grant sweep). No security fix was lost; the ob1-gate workflow rename lands as upstream intended with zero risk to this fork's actual CI path.
