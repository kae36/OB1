## Git drift on deployed schemas runs in BOTH directions -- checked each file individually rather than assuming one direction

**WHAT:** Compared every already-deployed schema/recipe file (`schemas/enhanced-thoughts`, `schemas/workflow-status`, `recipes/brain-health-monitoring`, `schemas/brain-stats-daily`, `schemas/crm-person-tiers`) between `HEAD` (kae36/personal @ ed47daf) and `origin/main` (this fork's main, tracking upstream NateBJones-Projects/OB1) to see if the anon-grant defect class shows up anywhere else, deployed or not.

**WHY this needed individual checks, not a blanket assumption:**
- **`schemas/enhanced-thoughts/schema.sql`: origin/main is AHEAD.** Upstream fixed the exact bug from [[project_supabase_default_privileges]] in commit `605e783` (removes `anon` from all three RPC grants), before this session ever ran the advisor. kae36/personal deployed an older pre-fix copy back in early August and never re-synced, so the live DB kept the vulnerable grants this whole time -- this is *why* the advisor re-run in this session caught it.
- **`schemas/crm-person-tiers/schema.sql` and `recipes/brain-health-monitoring/ops-views.sql`: kae36/personal is AHEAD.** These are the two capabilities the user's own Aug 5 incident patched (RLS + `REVOKE ALL` on the CRM tables; `security_invoker = true` on every `ops_*` view). origin/main still has upstream's older, unpatched version of both, because the brief already noted upstream was deliberately not told about that fix.
- **`schemas/workflow-status`, `schemas/brain-stats-daily`: identical, no drift.**

**HOW this changes the playbook:** The existing 6-step deploy playbook's step 1 (`git checkout origin/main -- <path>` to pull a capability) is fine for *new* capabilities, but must never be run against an *already-deployed* path as a "catch up with upstream" shortcut -- for two of five deployed files that would silently undo a security fix. Diff first, per file.

**IMPACT:** Extended `.planning/supabase-security/fix-lint-findings-2026-09-13.sql` to also revoke `anon` from `search_thoughts_text` (belt-and-braces; it's SECURITY INVOKER so RLS already blocks anon today, but upstream treats this as hygiene too) and documented the drift-direction finding inline in that file so it isn't lost. Not yet run by the user.

**Separately noticed, not deployed, lower priority:** `recipes/editorial-policy/schema.sql`'s `get_recent_audit_reports()` is `SECURITY DEFINER`, has no explicit GRANT at all (relies on Postgres's default EXECUTE-to-PUBLIC), and does zero `sensitivity_tier` filtering unlike its enhanced-thoughts siblings. Not in the brief's capability queue and not live, so no urgency, but worth a grant + a restricted-tier filter if it's ever adopted.
