## New live exposure found in `schemas/enhanced-thoughts`, missed by the Aug 5 remediation

**WHAT:** Advisor re-run (2026-09-13) surfaced 11 WARN + 2 INFO. Traced the two most important WARNs — `anon_security_definer_function_executable` / `authenticated_security_definer_function_executable` on `brain_stats_aggregate` and `get_thought_connections` — down to source and confirmed they are a real, currently-live exposure, not noise.

**WHY it matters:** Both functions are `SECURITY DEFINER` (bypass RLS on `thoughts` entirely) and are directly `GRANT EXECUTE ... TO anon` in `schemas/enhanced-thoughts/schema.sql`. Both take a caller-controlled `p_exclude_restricted BOOLEAN DEFAULT true` — anon can pass `false` and get restricted-tier thought stats (`brain_stats_aggregate`) or 200-char content previews (`get_thought_connections`) with zero authentication, via the public anon key alone. This is the same defect class as the Aug 5 incident ([[project_supabase_default_privileges]]) — RLS/advisor-green does not equal protected — but in a *different* schema (`enhanced-thoughts`) that the Aug 5 audit didn't touch, so it survived that remediation undetected until this advisor re-run caught it.

**HOW verified safe to fix:** Grepped `server/index.ts` (uses `SUPABASE_SERVICE_ROLE_KEY` directly, never calls either RPC by name) and every file under `/dashboards` (no references either). Nothing in this repo relies on anon being able to call these — the grant is unused boilerplate, so revoking it has zero functional impact.

**Other findings, lower priority:**
- 6 functions flagged `function_search_path_mutable` (WARN): `update_updated_at_column`, `update_task_after_maintenance_log`, `update_updated_at`, `match_thoughts`, `search_thoughts_text`, `upsert_thought` — hardening gap, not an active leak (`search_thoughts_text` is SECURITY INVOKER so RLS still applies for anon callers).
- `auth_leaked_password_protection` (WARN) — Auth dashboard toggle, low relevance for a single-user brain.
- 2 INFO (`rls_enabled_no_policy` on `crm_persons`/`crm_person_mentions`) — expected/benign, exactly the safe end-state the Aug 5 fix left behind (no policy + no grants = default-deny; service_role bypasses RLS). No action needed.

**Fix prepared, not yet applied:** Wrote `.planning/supabase-security/fix-lint-findings-2026-09-13.sql` (gitignored, same convention as the Aug 5 audit scripts) — REVOKE EXECUTE FROM anon, authenticated on both functions, ALTER FUNCTION ... SET search_path on the 6 flagged functions, ends with one verification SELECT (dashboard SQL editor only shows the last statement, per the known gotcha). Not run yet — per established preference, handed to the user to paste into the SQL editor themselves rather than run via the Management API.

**IMPACT:** Until the user runs this SQL, anon can currently read restricted-tier thought stats and content previews from the live `open-brain` project with no authentication. This should be treated as higher priority than the rest of the brief's queue.
