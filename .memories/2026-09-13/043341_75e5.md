## Enhanced-thoughts SECURITY DEFINER anon exposure -- fix applied and verified

**WHAT:** User ran the prepared SQL in the dashboard SQL editor. Verification query confirms `anon` and `authenticated` no longer have EXECUTE on `brain_stats_aggregate`/`get_thought_connections`; `anon` alone was stripped from `search_thoughts_text`; `search_path` is pinned on all 6 functions flagged for that.

**WHY it took extra decoding:** My own verification SELECT had a bug -- `array_agg(DISTINCT grantee::text)` referenced the raw ACL OID column instead of the joined `pg_roles.rolname`, so the CSV came back as OID lists (`16388`, `16484`, `16485`, `16486`) instead of role names. Decoded by comparing which OID is present/absent across the 8 rows against which REVOKE statements ran on which functions -- internally consistent, no ambiguity, but should write `r.rolname` next time instead of `a.grantee::text` in this kind of query.

**IMPACT:** Closes the exposure documented in checkpoint_8cfc5710 -- anon can no longer read restricted-tier thought stats/previews via these RPCs. This was flagged as higher priority than the rest of the brief's capability queue; that queue is now unblocked.
