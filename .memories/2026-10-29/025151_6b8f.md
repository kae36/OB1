### Why an edge, not an alias (learning)
- `upsertEntity` in `integrations/entity-extraction-worker/index.ts` (~line 412) checks aliases **before** exact-name upsert and **ignores entity_type**. Adding `kualico` as an alias on the project would have routed every future KualiCo mention to the project instead of the org. `graph_search` also matches aliases.
- **Rule:** only add an alias when the two names really mean the same thing (a merge). For "related to" use an edge, using the existing relation types (co_occurs_with, related_to, works_on, uses, located_in, member_of).

- New entities: `entities.created_at > now() - interval '2 hours'`.
- `supabase db query --linked` output starts with "Initialising login role..."; strip with `sed -n '/^{/,$p'` before jq.
- `entity_detail` does not return edge metadata.
