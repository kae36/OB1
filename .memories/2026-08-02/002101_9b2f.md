## Deployed brain-stats-daily heatmap RPCs

**WHAT:** Pulled `schemas/brain-stats-daily` from `origin/main`, deployed to live Supabase.

**WHY:** Next capability queue item after `brain-health-monitoring` (2026-08-02).

**HOW:** Installed `schema.sql` as-is via the Management API — no prerequisite issues this time (`enhanced-thoughts` already installed from the previous step covers its only dependency: `source_type`/`sensitivity_tier` columns). Adds 4 RPCs + 1 internal helper, all `SECURITY INVOKER`, execute granted to `authenticated`/`service_role` only (not `anon` — safer default per the schema's own security model):
- `brain_stats_daily(p_days, p_source_type, p_exclude_restricted)` — daily counts by `created_at`
- `brain_stats_daily_lifelog(p_days, p_exclude_restricted)` — daily counts for dated-event imports, bucketed by metadata life-date fields
- `brain_stats_daily_jsonb` / `brain_stats_daily_lifelog_jsonb` — JSONB variants that bypass PostgREST's 1000-row cap for multi-year windows

Smoke-tested both a 30-day window (real data returned, matches recent capture activity) and a 365-day JSONB call (23 days with activity in the last year).

**IMPACT:** Read-only aggregation RPCs, no core table changes. Dashboard wiring (`HeatmapSourceFilter.tsx`) is optional and not done — only relevant if/when `open-brain-dashboard-next` gets adopted.
