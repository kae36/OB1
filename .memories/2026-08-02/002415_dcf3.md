## Deployed crm-person-tiers

**WHAT:** Pulled `schemas/crm-person-tiers` from `origin/main`, deployed to live Supabase.

**WHY:** Next capability queue item after `brain-stats-daily` (2026-08-02).

**HOW:** Self-contained schema — new `crm_persons` + `crm_person_mentions` tables, no core `thoughts` modification (join table references `thought_id UUID` without a foreign key, deliberately, to keep `thoughts` untouched). Verified the `thought_id UUID` type assumption matches our live `thoughts.id` type before deploying. `crm_person_tiers(...)` RPC is `SECURITY INVOKER`, granted to `authenticated`/`service_role` only (not `anon` — same least-privilege pattern as `brain-stats-daily`). No hidden cross-schema dependencies this time (unlike `brain-health-monitoring`'s enhanced-thoughts/workflow-status surprise).

Full round-trip smoke test: inserted a test person (`known` tier, 0 mentions), queried via `crm_person_tiers()`, confirmed `relationship_tier`/`effective_tier`/`mention_count` all correct, deleted the test row.

**IMPACT:** Adds a "people in my brain" CRM layer with a 4-tier taxonomy (`connected`/`contact`/`known`/`unknown`) and activity-based auto-promotion to `connected`. Currently empty — no persons populated yet. Optional dashboard snippet (`dashboard-snippets/page.tsx`) not wired up, only relevant if `open-brain-dashboard-next` gets adopted.
