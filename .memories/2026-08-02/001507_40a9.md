## Deployed brain-health-monitoring (+ its hidden schema dependency)

**WHAT:** Pulled `recipes/brain-health-monitoring` from `origin/main` and deployed it to the live Supabase project, along with its true prerequisite chain.

**WHY:** Next item in the `bring-my-open-brain-up-to-date` capability queue. `ops-views.sql` requires `schemas/enhanced-thoughts`.

**HOW:**
- Discovered `schemas/enhanced-thoughts/schema.sql` replaces `upsert_thought()` with a version that writes to `status`/`status_updated_at` — columns it never creates itself. They only exist via `schemas/workflow-status`, which isn't listed anywhere in `enhanced-thoughts`'s stated Prerequisites. Installing `enhanced-thoughts` alone would have broken `capture_thought` on the next call.
- Applied in dependency order via the Supabase Management API (`POST /v1/projects/{ref}/database/query`, using the CLI's stored access token — no docker/psql needed): (1) `schemas/enhanced-thoughts/schema.sql`, (2) `schemas/workflow-status/migration.sql`, (3) `recipes/brain-health-monitoring/ops-views.sql`.
- Smoke-tested `upsert_thought()` post-install with a real insert, confirmed no error, deleted the test row (`8880938c-7411-4132-9ba1-49ba400eb140`) via direct SQL.
- Verified 5 of 8 `ops_*` views created (`ops_source_volume_24h`, `ops_recent_thoughts`, `ops_enrichment_gaps`, `ops_type_distribution`, `ops_sensitivity_distribution`); the 3 requiring `smart-ingest`/`entity-extraction` were skipped cleanly by the SQL's own `to_regclass` guards (as designed — not installed, not in scope).

**IMPACT:** `ops_type_distribution` shows 721/~770 thoughts as `unclassified` — expected, not a bug: the enhanced-thoughts backfill only promotes `metadata->>'type'` into the new column for a specific enum list, and most historical thoughts used types outside it (e.g. `observation`). Data's intact in `metadata`, just not column-promoted. Worth knowing before trusting that view at face value for historical data.

Files (`recipes/brain-health-monitoring/*`, brief update) staged for commit right after this checkpoint.
