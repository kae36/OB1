## Fixed ob1-gate.yml false-failure emails on every push

**Context:** User was getting repeated GitHub emails: "[kae36/OB1] Run failed: .github/workflows/ob1-gate.yml - kae36/personal (SHA)" with "No jobs were run", on every push to `kae36/personal` — even though the workflow's `on:` block only listed `pull_request`.

**Root cause:** `kae36/personal`'s copy of `.github/workflows/ob1-gate.yml` was a stale, pre-fix version. GitHub's workflow registration for that file's ID had gotten corrupted — confirmed via `gh api repos/kae36/OB1/actions/workflows`, where the run/workflow name fell back to the literal file path instead of "OB1 PR Gate" (a tell that GitHub couldn't fully parse/resolve the file). Once a workflow ID gets into this state, GitHub fires a failing "no jobs were run" run on *every* push, ignoring the declared `on:` triggers. Upstream had already hit and diagnosed this exact issue (see commit message on the old `ob1-gate.yml` rename: "renamed to force GitHub Actions to register a fresh workflow after the old workflow id began creating runs with zero jobs").

**Evidence trail:**
- `gh run list --workflow=ob1-gate.yml` showed 10+ consecutive `push`-triggered failures going back weeks, all "no jobs were run".
- `gh api .../actions/workflows` showed both `ob1-gate.yml` (id 287383123) and a dangling `ob1-gate-v2.yml` (id 290538537, not even present in the local working tree) both registered `active`, both showing path-as-name.
- `origin/main` had already moved the fix to `ob1-gate-v2.yml`; a further, more complete fix existed unmerged on `origin/codex/fix-ob1-gate-empty-runs` at commit `1e84f3f` ("Fix OB1 gate empty workflow runs") — renames back to `ob1-gate.yml`, switches trigger to `pull_request_target` + explicit `push:[main]` + `workflow_dispatch`, adds an `event_guard` job, and hardens the review step against script injection (moves PR-supplied fields like title/author into `env:` vars instead of inline `${{ }}` in `run:` blocks).

**Fix applied:**
1. `gh workflow disable ob1-gate.yml` and `gh workflow disable ob1-gate-v2.yml` — immediate stop to the emails.
2. `git cherry-pick 1e84f3f` onto `kae36/personal` — clean pick, only touched `ob1-gate.yml` + `ob1-pr-followups.yml` (commit `b35d5a6`).
3. `gh workflow enable ob1-gate.yml` — re-enabled with the fix in place. Left `ob1-gate-v2.yml` disabled since nothing backs it in the working tree.
4. Pushed `b35d5a6` to `origin/kae36/personal` after user confirmation.

**Impact:** No more false-failure emails on ordinary pushes to `kae36/personal`. `ob1-gate.yml` now only actually runs review logic on real PR events (`pull_request`/`pull_request_target`, non-closed) and no-ops cleanly (via `event_guard`) on push/workflow_dispatch. Also picked up an unrelated script-injection hardening fix as a bonus from the same upstream commit.

**Unrelated to the active brief** ("Bring My Open Brain Up To Date" — upstream capability adoption into the Supabase-backed OB1 instance); this was incidental repo-hygiene work triggered by the user noticing the emails.
