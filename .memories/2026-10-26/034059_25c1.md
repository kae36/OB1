## entity-extraction schema applied live (step 1 of entity-graph adoption)

**WHAT**
- Picked entity extraction (`schemas/entity-extraction` + `integrations/entity-extraction-worker`) as the next capability.
- Applied `.planning/supabase-security/entity-extraction-apply-2026-10-26.sql` via `supabase db query --linked -f` (user said "you run it").
  - Part A: upstream schema verbatim. Repo file is unchanged.
  - Part B: hardening.
- Created: `entities`, `edges`, `thought_entities`, `entity_extraction_queue`, `consolidation_log`, plus trigger `trg_queue_entity_extraction` (AFTER INSERT OR UPDATE OF content, metadata ON thoughts).

**Verified live**
- RLS on all 5 tables. ACL is postgres + service_role full access, `authenticated` read-only, no anon.
- `queue_entity_extraction()` proacl = postgres + service_role only; search_path = public, pg_temp. `has_function_privilege` anon/authenticated = false.
- Queue is empty (no backfill yet). enhanced-mcp `graph_search` returns `{"results":[],"total":0}` instead of failing on missing tables.

**WHY this pick (alternatives rejected)**
- consolidation-workers: no-op on this data. The metadata worker needs `metadata.confidence` < 0.7, and 0 of 814 rows have confidence. The bio worker needs person_note/decision/journal types; there are none. Its README cites a non-existent `schemas/knowledge-graph`; `consolidation_log` actually comes from entity-extraction.
- chrome-capture-extension: needs undeployed open-brain-rest.
- hermes-agent-memory: Hermes not installed; needs agent-memory schema + API.
- gmail-smart-pull: only emits a pack; no working importer.

**Learned**
- Live `pg_default_acl`: postgres-owned tables → postgres + service_role only. Functions → anon + authenticated EXECUTE. The landmine catalog's "service_role-only" for this function was wrong. Addendum written.
