## Upstream PR diffs read: #490 fixes the enhanced-mcp blockers client-side; #363 does not (2026-09-20, read-only)

### PR #490 (TomKeyser, 1 file `integrations/enhanced-mcp/index.ts`, +56/-25, open since 2026-09-02, mergeable, review required)
Independently reports and fixes the same defects found in this session:
- Stops sending `exclude_restricted` / `start_date` / `end_date` in the RPC `p_filter` (both `search_thoughts_text` and the getting-started `match_thoughts` treat it as `metadata @> filter`, so every query matched zero rows). Restricted and date filtering moved to client-side post-filters. This confirms the semantic-mode cause I had flagged as unconfirmed.
- `brain_capture_thought` accepts `{id}` as well as `{thought_id}` (no more false error), and persists the embedding with a follow-up `update` (the RPC's INSERT never wrote it). Reports explicitly if that update fails.
- `get_thought` takes a UUID string instead of an integer.
- Does NOT fix: `update_thought` and `related_thoughts` (integer ids; #506 drops update_thought), and the detected `sensitivity_tier` / importance / quality still are not persisted (RPC reads them only from `p_payload.metadata`; stored tier stays `standard`, importance 50, quality 70).
- No database change needed: edge-function redeploy only.

- `search_thoughts_text` learns `start_date` / `end_date` / `exclude_restricted` as reserved control keys applied in SQL (would fix text search server-side, including for rest-api).
- `upsert_thought` rewritten with original-fingerprint dedup and a user-edit guard; still returns `{id, fingerprint}` (adds `matched_via`), still does NOT insert the embedding, still ignores top-level `sensitivity_tier`. So it does not fix the capture problems.
- Adds opt-in `match_thoughts_superseded_aware` (only if `thought_edges` exists; would need REVOKE FROM PUBLIC by our rule since it only GRANTs to service_role).
- Replaces the live function used by workflow-status etc.: large change, low benefit for us. Not recommended.
- Caveat: first ~150 diff lines (README/metadata + start of the search function) were skimmed via the PR description, not read line by line.
