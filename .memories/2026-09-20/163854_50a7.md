## rest-api capture path review (2026-09-20, read-only): not adoptable as shipped against the live DB

Read `integrations/rest-api/index.ts` (handleCapture, handleSearch, routing, extractThoughtId, validateId) and the 09-13/09-19 landmine catalog. Nothing was deployed or written.

### Findings
- **`/capture` will report a false 500 after storing the row.** `extractThoughtId` only accepts digit-only ids. The live `thoughts.id` is UUID and `upsert_thought` returns `{id, fingerprint}`, so it throws "upsert_thought returned no result" (caller sees `internal_error`). Same failure as enhanced-mcp. A retry hits the fingerprint conflict and updates the existing row.
- **Every `/thought/:id` route is unreachable.** Routing regexes are `(\d+)` for GET/PUT/DELETE, `/connections`, `/enrich`, and `validateId` is digits-only, so no UUID id can be addressed. Same for `/entities/:id` and `/ingestion-jobs/:id` (bigint assumption).
- **`/search` text mode returns nothing by default.** `excludeRestricted` defaults true and puts `exclude_restricted: true` into `p_filter`, which `search_thoughts_text` matches via `metadata @> p_filter`. Passing `exclude_restricted:false` avoids the empty result but then no restricted filtering happens in text mode (no post-filter).
- **`/search` semantic mode is probably fine**: it passes `filter: {}` to `match_thoughts` and post-filters restricted rows. This also supports the (still unconfirmed) theory that enhanced-mcp's semantic search was empty because it put `exclude_restricted` into the match_thoughts filter.
- **Silent data loss on capture (same `_shared/helpers.ts` pipeline and RPC as enhanced-mcp):** `upsert_thought` ignores top-level `p_payload` fields, so detected `sensitivity_tier`, computed importance/quality (RPC defaults 50/70), and the embedding are not persisted. Not verified live for the embedding.
- Landmine catalog: `rest-api` itself has no SQL; its prerequisites (`enhanced-thoughts`) are live and fixed. `smart-ingest`, `knowledge-graph` routes need tables that are not deployed.

### Decision
Do not adopt `rest-api` as shipped. The blocker is upstream-vs-live drift in the `upsert_thought` contract and UUID ids, shared with `enhanced-mcp` and `smart-ingest`, not anything specific to rest-api. Adopting anything in the queue that captures through `_shared/helpers.ts` needs one patch to the RPC contract first, or should wait.

### Impact
Stock `open-brain` connector remains the only working capture/search path. Remaining queue items that write thoughts (`smart-ingest`, `chrome-capture-extension`, `auto-capture-claude-code`) likely share the same problem.
