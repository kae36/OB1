## enhanced-mcp verification (2026-09-20): classifier and restricted-write gate work; capture reports a false error and both search modes return nothing

### What was tested
Open item 1 from the brief: write path, auto-classification, sensitivity filter. Read `integrations/enhanced-mcp/index.ts`, `_shared/helpers.ts`, `_shared/config.ts` and `schemas/enhanced-thoughts/schema.sql`, then probed the live connector.

### Results
- **Classification: works.** One labeled test thought was captured with `enrichment_status: complete` and LLM-assigned type, topics, action items. So `OPENROUTER_API_KEY` is set and valid.
- **Restricted-content write gate: works.** A fake `password: ...` capture was rejected ("Restricted thoughts are local-only...") and nothing was stored. Restricted content is blocked at capture, so the read-side filter can only be exercised if a restricted row already exists (not verified, none known).
- **Write path: row is stored, but the tool returns `Error: upsert_thought returned no result`.** The test row exists (source_type `verification-test`, UUID `bc4c04c5-a790-4acb-8e97-f5f4ab6c0f01`). Cause, from the repo schema: the live `upsert_thought` returns `{id, fingerprint}`, and the function expects `{thought_id, action, content_fingerprint}`.
- **Search: both modes return zero results** even for "Supabase" (text and semantic). Text mode cause is visible in the repo SQL: the function sends `p_filter` containing `exclude_restricted: true` and `search_thoughts_text` matches it with `metadata @> p_filter`, which no row satisfies. Semantic-mode cause NOT confirmed (`match_thoughts` definition not read; likely the same filter).

### Contract mismatches found in code (not yet confirmed as live behavior beyond the stored row)
- `thoughts.id` is UUID; the function's `get_thought` / `update_thought` take integer ids, so they cannot address any row.
- `upsert_thought` reads `type`, `importance`, `quality_score`, `sensitivity_tier` from `p_payload->'metadata'` and ignores the top-level payload fields. The stored test row shows importance 50 / quality 70 (the RPC defaults), not the values the function computed. So the detected sensitivity tier (personal) is probably NOT persisted, and the embedding passed at top level is probably dropped (embedding presence on the test row not checked).
- Importance is 0-6 in the function but 0-100 in the RPC.

### Impact
- The `open-brain-enhanced` write tool and search tools are not usable as deployed. Read tools that do not depend on the filter (`brain_list_thoughts`, `brain_thought_stats`) work; the stock `open-brain` connector should be preferred for capture and search meanwhile.
- The read-side sensitivity filter remains unverified.
- The test thought is still in the DB.
